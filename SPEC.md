# Bunker Live — Technical Contracts (v1)

**Проект:** `D:/Hermes/ideas/bunker-live/`
**Стек:** Node.js 22 + Express + Socket.IO + vanilla ES-модули в браузере. **Нулевая сборка.** Запуск: `npm install && npm start` → http://localhost:3000

Все артефакты — **на русском языке** (интерфейс, карточки, подсказки). Термины-латиница (WebSocket, Socket.IO) допустимы.

---

## 1. Схема карточек (JSON)

Каждый файл колоды — в `server/game/data/<имя>.json`, кодировка UTF-8, без BOM.

```json
{
  "category": "profession",
  "label": "Профессия",
  "icon": "🛠",
  "cards": [
    {
      "id": "prof_01",
      "title": "Хирург",
      "text": "Оперирует в полевых условиях, знает анатомию и умеет стерилизовать инструменты подручным.",
      "tags": ["медицина", "наука"],
      "tip": "Уточни, есть ли в бункере медпункт. Если да — ты незаменим, и это твой главный аргумент."
    }
  ]
}
```

**Правила заполнения:**
- `id` — уникальный внутри файла, формат `<префикс>_NN` (двузначный номер, начиная с 01).
- `title` — короткое название карточки (1-5 слов), без точки в конце.
- `text` — 1-2 предложения, 80-200 символов. Конкретика, а не общие слова.
- `tags` — 2-4 строчных тега через запятую, для будущей фильтрации.
- `tip` — **обязательно**. Подсказка новичку: как этим аргументировать в споре за место. Одно предложение, обращение на «ты», 60-160 символов. Это ключевая фича игры — не оставляй заглушек.

**Тон:** мрачноватый, с чёрным юмором, но без пошлости, сленга и оскорблений. Никаких реальных имён, брендов, политики.

**Запрещено:** дубликаты `title` внутри одного файла и между файлами; пустые поля; placeholder-тексты вида «Описание 1».

## 3. Особый формат `specials.json`

Спец. возможность — разовое действие. Дополнительно к общим полям каждая карта имеет:

```json
{
  "id": "spec_01",
  "title": "Вскрыть чужую карту",
  "text": "Ты можешь заставить любого игрока открыть одну закрытую характеристику до голосования.",
  "tags": ["контроль", "информация"],
  "tip": "Держи до момента, когда против тебя собираются голоса: вскрытая чужая слабость мгновенно меняет расклад.",
  "effect": "reveal_other",
  "targeting": "one_player"
}
```

- `effect` — строго одно из: `reveal_other`, `swap_card`, `immune_vote`, `double_vote`, `cancel_vote`, `peek_other`, `heal_self`, `boost_self`, `extra_time`, `return_player`, `reroll_card`, `silence_player`.
- `targeting` — строго одно из: `self`, `one_player`, `all`, `none`.

## 4. Формат `catastrophes.json` и `bunker.json`

**Катастрофа** (дополнительно к общим полям):

```json
{
  "id": "cat_01",
  "title": "Ядерная зима",
  "text": "Обмен ядерными ударами поднял в атмосферу пепел: солнце скрылось на годы, температура упала до −40 °C.",
  "tags": ["холод", "радиация"],
  "tip": "Смотри на здоровье и профессию: радиация и холод убьют всех, кто не может чинить фильтры и греть убежище.",
  "duration": "5 лет",
  "severity": 5,
  "threats": ["Радиационный фон", "Экстремальный холод", "Голод"]
}
```

- `severity` — целое 1-5 (насколько жёсткая катастрофа).
- `threats` — 2-4 ключевые угрозы, которые катастрофа создаёт для бункера.
- `duration` — строка вида `"5 лет"`, `"18 месяцев"`, `"3 года"`.

**Бункер** (карта свойства убежища):

```json
{
  "id": "bunk_01",
  "title": "Военный бункер",
  "text": "Бетонная крепость на 40 человек с автономной вентиляцией и армейскими пайками.",
  "tags": ["защита", "армия"],
  "tip": "Если в карте есть защита и запасы — требуй в команду ремонтников и медиков, а не просто «хороших людей».",
  "kind": "advantage",
  "area_sqm": 420,
  "food_units": 14,
  "sleeping_rooms": 6,
  "items": ["Дизель-генератор", "Фильтр воздуха", "Оружейный сейф"]
}
```

- `kind` — строго `advantage` (плюс убежища) или `hazard` (проблема убежища).
- `area_sqm` — целое 80-900. `food_units` — целое 0-24. `sleeping_rooms` — целое 1-12.
- `items` — 3-5 предметов, которые уже есть внутри.

Игра соберёт бункер из **3 advantage + 2 hazard** карт. Учитывай это: hazard-карты должны быть реальными проблемами, advantage — реальными плюсами.

## 5. Формат `help.json`

Справка, показываемая в интерфейсе. Строго такая структура:

```json
{
  "phases": [
    {
      "id": "reveal",
      "title": "Раскрытие характеристик",
      "short": "Открой карты и объясни, чем полезен.",
      "text": "В каждом раунде ты открываешь часть своих характеристик...",
      "tips": ["Не читай карту дословно — сразу говори, какую проблему бункера она решает.", "Второе правило."]
    }
  ],
  "faq": [
    { "q": "Сколько мест в бункере?", "a": "По умолчанию — половина игроков с округлением вниз: 6 игроков → 3 места, 8 → 4, 12 → 6. Хост может задать фиксированное число." }
  ],
  "glossary": [
    { "term": "Временный лагерь", "definition": "Место перед бункером, где находятся все выжившие до конца игры." }
  ]
}
```

- `phases` — ровно 6 записей, `id` строго из набора: `lobby`, `reveal`, `discussion`, `voting`, `defense`, `finale`.
- `faq` — минимум 10 вопросов (включая: сколько мест в бункере, сколько раундов, что делать если не успел проголосовать, можно ли пропустить голосование, что такое спец. возможность, что видят другие игроки, как присоединиться по коду, что если игрок вышел из игры, сколько карт открывается за раунд, что происходит с изгнанным).
- `glossary` — минимум 8 терминов.

## 7. Протокол Socket.IO (справочно, для согласования с UI)

**Клиент → сервер:** `room:create`, `room:join`, `room:leave`, `settings:update`, `game:start`, `turn:reveal`, `phase:advance`, `vote:cast`, `vote:skip`, `defense:done`, `note:set`, `special:use`, `chat:send`

**Сервер → клиент:** `state` (персональный снапшот), `toast`, `log:append`, `game:over`

Состояние каждой фазы приходит целиком в `state.phase` — клиент только рендерит, своей логики переходов не держит.
